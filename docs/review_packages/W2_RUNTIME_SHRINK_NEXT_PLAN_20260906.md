## 先做什么

### 1. 发布前确认

由执行方在本地完成：

- 确认工作区提交只包含本轮瘦身和必要测试/文档；
- 生成可回滚的本地发布包；
- 记录新 commit、文件清单和校验值；
- 不改 schema，不调用 Provider，不写生产。

若发现未预期改动，停止发布并回退到检查，不进入线上。

### 2. 部署瘦身版本

只有发布前确认通过后，才部署到现有线上环境。部署必须保持：

- schema 不变；
- 正式推荐关闭；
- 不停采集和结算 writer；
- 保留现有回滚版本；
- 不访问 GitHub/GHCR。

### 3. 线上只读验收

部署后只检查：

- API、worker、scheduler、web 健康；
- 运行版本四处一致；
- API/dashboard/notification 使用同一 V4 身份；
- 缺失或非法 V4 时为 `NOT_READY`、无 pick；
- F7/F8、Elo、身价、阵容调整不改变 lambda；
- provider、生产写入、正式推荐状态符合预期。

任一项失败，立即回滚；不在生产现场修补。

## 部署后任务

部署验收通过后进入“运行观察”，不立即启动新模型研究：

- 观察一轮完整采集周期，确认瘦身没有破坏采集、结算、ledger、raw 和历史记录；
- 记录真实的 V4 READY/NOT_READY、市场候选和通知一致性；
- 仅处理运行故障，不调整模型、阈值或因子。

观察期结束后再做一次决策：

- 若链路稳定：另立模型研究计划，先做输入覆盖和数据可行性核查；
- 若链路异常：先修复运行链，暂停模型研究；
- 不以观察结果宣称预测准确或盈利。
