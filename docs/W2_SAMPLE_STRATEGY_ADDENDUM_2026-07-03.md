# W2 样本策略澄清与修订（附录）

出具：Claude ／ 2026-07-03 ／ 修订对象：`W2_ACCURACY_UPGRADE_TASKS_2026-07-02.md` 之 #131 验收条款
背景：#124–#133 已完成，团队将 #131 的 n≥200 理解为"自家 settled reproducible lock 样本"，由此担心世界杯收官后无样本可积累、需等到下届大赛。该理解比原意窄，本附录给出权威口径并修订验收。

## 1. 三个门槛各挡什么（先消除误解）

| 门槛 | 控制的事情 | 挡不挡出推荐 |
|---|---|---|
| #131 n≥200 | λ 默认参数能否从 BASELINE_PRIOR 切到 fitted | **不挡**。BASELINE_PRIOR 是合法运行态，FORMAL 照常出 |
| #132 桶内 n≥30 | 能否展示实际赢盘率/Brier（否则"观察中 n/30"） | **不挡**。它是赛后展示口径，且 `not_a_formal_gate=true` |
| #125 ISC≥3 覆盖率 70% | 当日数据完备度（信号源个数），按场判定 | 只挡**数据不完备的单场**，与样本积累无关 |

结论：系统今天就处于可出推荐状态。等样本等的只是"校准标签升级"和"表现百分比展示"，不是推荐本身。

## 2. #131 语料修订（核心修正）

**拟合语料 ≠ 自家锁定样本。** λ 拟合的本质是"赛前输入 → 真实比分"的映射标定，任何能重建 as-of 正确赛前特征的**历史完场比赛**都是合法样本，与 W2 是否对该场出过推荐无关。自家 lock 样本只在 #132（评估我们自己的推荐表现）中不可替代。

修订后的语料定义（按赛事 profile 分别建）：

- 来源：A2 回填管线取过去 2–3 个赛季的完场比赛（fixtures by team / league season 端点，休赛期配额充裕，仍走 quota_budget）；Gate3 历史数据集；必要时人工策展公开赛果数据集（只取比分与日期，方式同 A4，禁爬虫红线不变）。
- 特征：与线上一致的赛前输入（滚动 xG、Elo、身价、休息日），一律用该场 kickoff 之前的数据重建，泄漏检查单测强制。早年缺 xG 的赛季要么剔除、要么以进球代理并打 `PROXY_FEATURE` 标记单独评估。
- 目标：真实比分的 log-loss / CRPS。**市场赔率与盘口不得出现在特征或目标中**（红线不变）。
- 规模参照:五大联赛单季约 1700 场、欧洲杯 51 场、世界杯 64–104 场——n≥200 在任何一个联赛 profile 上一季即满足，**不存在等到 2034 的问题**。

修订验收条款（替代原文"n≥200 settled reproducible lock samples"）：

> n≥200 指**该赛事 profile 拟合语料中的历史完场样本数**（as-of 特征可重建、无泄漏），与 settlement/lock 无关。holdout log-loss ≤ baseline prior 才切默认参数；lock 样本继续只服务 #132。`s2_gate.n_min` 的语义随本条更新。

## 3. 分赛事校准 profile（防止错误迁移）

世界杯拟合出的参数（中性场、国家队、赛会制）**不得**直接套联赛。按 profile 分别拟合并版本化：

- `world_cup / euro`：中性场 HA gate（#124a）生效，用国际赛语料。
- `top5_league.{league_id}`：主场优势真实存在（HA 参数按联赛拟合）、总进球水平各异，用该联赛自己 2–3 季语料。
- calibration 配置按 profile 存：`config/calibration/{profile}.lambda_fit.v1.json`，lock snapshot 照常记录版本。

## 4. 从现在到联赛开赛的执行时间表

**现在 → 世界杯结束（约 7/19，剩余淘汰赛不足 20 场）**
1. 系统保持 BASELINE_PRIOR 正常出 FORMAL、锁定、结算——这些是 #132 的种子样本，一场都别浪费。
2. 用世界杯已完场比赛（截至今日约 90 场）立即做第一轮 walk-forward **报告**（不切参数，n 不足如实标注）。这一步现在就能跑，用来验证拟合管线本身。

**休赛期（7/20 → 8 月初）— 真正的主战场，全部离线，不依赖比赛日程**
3. A2 管线回填五大联赛过去 2–3 季完场数据（配额空窗期执行，留 raw payloads）。
4. 构建各联赛拟合语料 → 按 profile 完成 λ 拟合 → holdout 达标者在开赛前切默认参数。
5. 复制世界杯的数据资产模式到联赛（这是 8 月能不能达标 ISC≥3 的**真正前提**，现有 config 只覆盖世界杯 48 队）：
   - 各联赛俱乐部身价静态映射 `config/team_values/{league}.v1.json`（Transfermarkt 联赛页，人工策展，同 A4 流程）；
   - 俱乐部 Elo 静态映射（ClubElo 类公开来源，同 A5 流程）；
   - team_ids 对齐表、H2H 回填、赛事 profile 配置（HA、赛程密度）。
6. 用上季最后 4–6 轮做一次端到端影子演练：假装是当年比赛日，走完"payload → FORMAL → lock → settle → 审计表"，验证联赛模式下全链路与 ISC 覆盖率。

**8 月联赛开赛后**
7. 带 fitted 参数上线；五大联赛每周约 40–50 场，按 FORMAL 转化率估算，#132 首批桶 3–6 周内达 30，逐桶从"观察中"转为实际表现展示。
8. 每周跑 calibration_report；预测与实际差 >5 个百分点触发按 profile 重拟合（改参数须过 holdout，不改阈值）。

## 5. 不变的部分

#132 桶内 n≥30 才出百分比：**维持不动**。这是诚实性约束，样本少时显示"观察中"就是正确行为，任何赛事都不豁免。#125 的 70% 是数据完备度指标，联赛数据资产（第 4 节第 5 条)备齐即可达标，与时间积累无关。

## 6. 一句话

不用等任何世界杯：推荐现在就出（BASELINE_PRIOR 是合法状态）；拟合样本从历史赛季来（一季联赛 ≈ 1700 场，休赛期离线搞定）；只有"展示自家实际赢盘率"必须诚实地随真实使用积累，而它从来不挡推荐。休赛期的核心任务是把身价/Elo/历史三类数据资产从"世界杯 48 队"复制到各联赛俱乐部。
