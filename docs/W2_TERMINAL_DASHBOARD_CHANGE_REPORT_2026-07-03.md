# 修改报告：Dashboard 页升级为交易终端风格（供技术员验收）

修改人：Claude ／ 2026-07-03（v2 紧凑决策版）／ 修改基线：`9797819`（A-QUOTA-INCIDENT-002 之后的工作区）

## 0-bis. v3 修订（对齐网格版，修复宽屏"死空间 + 逐行废话"问题）

老板对 v2 实际截图的反馈：宽屏下中间弹性列拉出大片空白、右侧数字不成列、每行下面拖一条几乎相同的灰色元信息。v3 改为真正的终端对齐网格：

1. **固定十列网格 + 列头**：时间｜联赛｜对阵｜状态｜原因｜盘｜差｜ISC｜走势·参照｜as-of。所有行共用同一列模板，数字列右对齐、等宽字体，垂直可扫；新增表头行；行斑马纹。
2. **重复信息降噪**：每行的"状态：xxx（…）"整句、盘口走势整句、数据三项、完整 as-of 全部移入该行的 title 悬停提示（信息不删除、审计可查），可见区只保留：状态徽章 + 原因短语 + 数字列 + 走势模式词 + HH:MM。"参照·未验证"声明由列头"走势·参照"与页脚承担，不再每行重复。
3. **数据异常才占视觉**：新增"数据未齐"琥珀角标（赔率/首发/xG 任一非 READY 时出现在原因列），全就绪时不显示任何数据状态文字。
4. **FORMAL 行**：与表格同列对齐的主行 + 一行绿色决策条（推荐主张 + EV 等宽高亮 + 我们的盘/市场盘/差距/比分 top3 合并、超宽截断）。
5. 新增辅助：`_number_cell`（数字列格式化，缺失显示 —）、`_data_quality_flag`；`_compact_numbers` 移除。窄屏（<900px）自动收缩为六列。
6. 回归：六场景全部复跑通过（空日/50 场排序与 EV/无正式日无方向无比分/转义/禁词/text 路径不受影响），输出仍逐字节确定。

## 0. v2 修订（按老板"决策系统、不是资讯网站"的要求压缩排版）

在 v1 终端风格基础上进一步压缩，定位从"逐场卡片阅读"改为"决策行情条扫读"：

1. **非 FORMAL 场次压成单行行情条**：`时间 | 联赛 | 对阵 | 状态（原因） | 盘/差/ISC 数字列`，附一行 10.5px 灰色元信息（说明/走势/数据/as-of，超宽自动省略号截断）。每场高度从约 7 行文本降到约 2 行（约 34px），50 场一屏半扫完。
2. **FORMAL 压成三行决策块**：首行同上（右侧换成 `EV +x.x%` 等宽高亮），第二行绿色推荐主张（推荐：全场让球，看 …），第三行合并"我们的盘/市场盘/差距 ｜ 比分 top3"，元信息一行截断。所有决策要素零滚动可见。
3. **头部合并**：标题、as-of、状态汇总、过滤 chips、搜索、联赛、排序全部并入一个吸附置顶块（两行），删除独立状态行与段落标题，正文从第一屏第 3 行就开始出比赛。
4. **间距全面收紧**：卡片间距 6px→2px、内边距 9/14→3/10、基准字号 13→12.5、表格与折叠区同步缩小；页面最大宽度 1280→1360 提高单行信息量；窄屏（<760px）自动降为三列布局。
5. **回归修复**：v1 页脚文案含"推荐比分"四字，会违反既有测试"无正式推荐日不得出现该词"（`test_render_html_no_formal_day_does_not_fake_recommendations_or_scorelines`）。已改为"非 FORMAL 场次不显示推荐方向与比分参考"。
6. 新增辅助函数 `_compact_numbers`（从 pricing_shadow 提取 盘/差/ISC 行情列）；`_html_match_card` 重写为行情条结构。既有测试契约（match-card 计数与顺序、"推荐：全场让球，看 …"、"状态：观察"、"推荐比分"仅正式日出现、每场单次判定、空日文案、禁词、确定性）在隔离环境六个场景全部复核通过。

以下为 v1 报告原文（视觉基调、兼容性清单与验收步骤仍然有效）。

## 1. 改了什么

**唯一改动文件：`src/w2/reporting/report_generator.py`**（重写 `_render_html_report`，新增 `_html_match_card` 辅助函数与 `_TERMINAL_CSS` / `_TERMINAL_JS` / `_STATE_CHIP_LABELS` 三个模块常量）。改动限定在 HTML 展示层，markdown/text 输出、decide_match、runner、CLI、审计表**零改动**。

具体变化：

1. **交易终端视觉**：深色终端底（#0a0e14）、等宽数字、状态左边条色标（正式=绿 / 观察=灰蓝 / 数据不足=琥珀 / 盘口未就绪=红 / 已锁定=紫）、置顶吸附状态栏（标题 + as-of + 状态计数一眼可见）。
2. **优质比赛快速筛选**（针对五大联赛单日几十场）：
   - 正式推荐卡片恒置顶，**组内按 EV 降序**——从上往下就是"今天最值得看的顺序"；
   - 状态过滤 chips（全部/正式/观察/数据不足/盘口未就绪/已锁定，带计数）；
   - 联赛下拉过滤 + 球队搜索框；
   - 排序切换：正式优先·EV 降序（默认）/ 开球时间 / 差距绝对值。
   - 以上全部为**纯客户端显示过滤**（约 60 行内联原生 JS），不发任何请求、不改任何数据。
3. **加载速度**：页面是零依赖静态单文件——无外部字体、无 CDN、无框架、无 API 轮询，12 场约 17KB、50 场估算约 60KB，打开即渲染。若此前"加载慢"来自打开旧 SPA 或直连 /v1/dashboard，改用 runner 预生成的 `runtime/reports/w2_day_<足球日>.html` 即可。
4. **审计明细不丢**：原"正式推荐表 / 非 FORMAL 判定表（blocker 解释）"完整保留，收纳进两个折叠区（`<details>`），默认收起、点开即查。
5. **红线不动**：FORMAL 才渲染方向/比分；非 FORMAL 渲染原因码中文解释；盘口走势恒标"参照·未验证"；禁词 guard 对整个 HTML 生效；as-of 强制；输出确定性（同一 payload 两次渲染逐字节一致）；页脚固定声明"非 FORMAL 场次不显示推荐方向与推荐比分"。

## 2. 兼容性（既有测试契约逐条对齐）

以下断言在本次修改中全部保持成立（我已在隔离环境逐条冒烟复核）：

- `<!doctype html>`、标题"W2 足球日报告 · {day} · 临场最终"、副标题"场次 N · 正式推荐 N"、状态汇总"场次 N · 正式 N · 观察 N · …"原样保留；
- `class="match-card {state}"` 结构保留，正式卡片先于观察卡片，卡片总数等于场次数；
- html 路径不重复调用 decide_match（每场判定一次，`test_render_html_uses_one_decision_per_match_for_scorelines` 兼容）；
- 空日：仍输出"今日正式推荐：0"与"当前无 FORMAL + recommendation_id + future kickoff"，新增"本足球日无场次"空态；
- 无 FORMAL 日不出现"推荐：全场让球"与"推荐比分"；
- 非 FORMAL 判定表的 blocker code 与中文解释（A-134B）原样保留；
- runner 的 `w2_day_{football_day}.html` 命名与 sink 逻辑未触碰。

新增行为（不与旧断言冲突）：正式组内 EV 降序；卡片带 `data-state/league/teams/ev/edge/ko` 属性；HTML 对队名等全部转义（含恶意字符串用例已验证）。

## 3. 技术员验收步骤

```
# 1) 单测（重点三个文件，然后全量）
pytest tests/unit/test_report_generator_output.py tests/unit/test_report_generator_cli.py tests/unit/test_report_runner.py -q
pytest -q

# 2) 真实 payload 出页
python scripts/generate_w2_report.py --url http://<staging>/v1/dashboard?window=today --format html --output /tmp/w2_day_check.html
# 浏览器打开，核对：正式置顶且 EV 降序、chips 计数与状态行一致、过滤/搜索/排序可用、
# 折叠表内容完整、无方向泄漏到非 FORMAL 卡片

# 3) runner 常规链路（健康门禁 + 落盘命名）
python scripts/run_w2_report_runner.py --base-url http://<staging> --format html --sink file
```

验收红线：禁词扫描（含"方向未识别"）不出现；同一 payload 重复生成 diff 为空；50 场规模页面 <100KB。

## 5. 建议的刷新节奏（与"加载慢"根治相关）

页面本身瞬时打开；数据新鲜度靠重新生成：早间 1 次 + 开赛前每小时 1 次 + 临场 30 分钟 1 次（runner 定时任务，健康门禁失败不覆盖旧页）。nginx 指向 `runtime/reports/` 目录即可按日归档访问。
